项目周期: 3周 | 当前阶段: 第一阶段 (基础建设与鉴权)

一、 总体进度规划 (三周概览)
我们只有三周时间，必须采用“小步快跑、阶段验收”的敏捷模式：
• 第一阶段 (第1-4天)：基建跑通，数据库统一，登录注册业务闭环。
• 第二阶段 (第5-9天)：教授端业务写入 (积分工单) 与 学生端基础展示。
• 第三阶段 (第10-14天)：大厅公共展示 (排行榜、滚动动态) 与 复杂多表查询联调。
• 第四阶段 (第15-21天)：全局系统测试、UI美化、Bug修复及答辩材料准备。
二、 第一阶段详细任务拆解 (限时 3-4 天)
👨‍💻 组员 2：后端核心与鉴权（组长：石雯珏 / Noa）
作为组长，你需要在这几天内为团队铺好路，你的任务是本阶段的核心阻塞点。前置任务必须由你先完成，其他组员才能顺利推进。
【任务 1】统一数据库模型 (第1天)
• 负责文件: 新建 `hogwarts.sql`
• 具体事务: 编写完整的 DDL 建表语句，包括 `sys_user`、`house`、`point_log`。必须在此文件中写好核心的触发器 `trg_after_point_insert`。写完后分发给全组，要求每个人在本地运行。
【任务 2】初始化后端项目 (第2天)
• 负责文件: 新建 `app.py`, `requirements.txt`, `.env`
• 具体事务: 搭建 Flask/FastAPI 基础路由，配置好 PyMySQL 连接本地数据库的代码，配置跨域 (CORS)。
【任务 3】编写鉴权 API 接口 (第3-4天)
• 负责文件: `app.py` 或新建 `auth_api.py`
• 具体事务: 
  1. 开发 POST `/api/register`，实现密码哈希加密及用户名唯一性校验。
  2. 开发 POST `/api/login`，校验成功后生成 Token/Session，返回 role。
  3. 开发 POST `/api/logout`。
👩‍💻 组员 1：前端开发（甄珍）
前端同学本阶段重点在于搭出架子，并完成复杂的注册表单联动交互。
【任务 1】初始化前端项目与公共页面 (第1-2天)
• 负责文件: 新建前端目录结构，创建 `login.html`, `register.html` (或 Vue 组件)
• 具体事务: 绘制登录和注册界面的 UI，确保输入框和按钮的样式整洁。
【任务 2】表单逻辑与接口联调 (第3-4天)
• 负责文件: 对应页面的 JS 脚本
• 具体事务: 
  1. 注册逻辑: 监听“角色”下拉框，若选“学生”，显示并必填“所属学院”；若选“教授”，隐藏学院下拉框。
  2. 接口对接: 对接 Noa 写的 `/api/register` 和 `/api/login` 接口。
  3. 路由跳转: 登录成功后，将 Token 存入本地。若 role=0 跳学生端，role=1 跳教授端。
👨‍💻 组员 3 (余雨航) & 组员 4 (费翔鸿)：后端业务
由于第一阶段的核心是基建和鉴权，你们两位的 API 暂不需要立刻与前端联调。本阶段主要任务是“环境同步”与“API预研”。
【任务 1】同步开发环境 (第1-2天)
• 负责文件: 无需新建，负责拉取代码
• 具体事务: 拿到 Noa 写的 `db_hogwarts.sql`，在自己电脑的 MySQL 跑通建库。拉取 Noa 的 Python 代码，确保自己电脑能正常启动服务。
【任务 2】SQL 语句预研与 API 骨架搭建 (第3-4天)
• 余雨航 (业务写入):
  新建 `professor_api.py`，根据 API 文档写出 `/api/students` 的底层 SQL。在本地数据库手动测一下 Noa 写的触发器能不能用。
• 费翔鸿 (业务读取):
  新建 `student_api.py` 和 `public_api.py`。在本地数据库手动写 SQL 预演：尝试写出按 `total_points` 降序的查询，以及带 `LIMIT 10` 的动态连表查询。
