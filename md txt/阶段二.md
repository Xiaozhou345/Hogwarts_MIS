阶段目标: 实现教授端的积分写入（触发总分更新）与学生端的基础积分信息读取与展示。

一、 阶段总结与回顾
恭喜团队顺利完成第一阶段！经过验收，底层数据库模型与 sys_user、house、point_log 表的构建已完备，注册/登录等鉴权机制也已在前后端打通（代码文件 auth_utils.py、app.py、login.html 均运行正常）。现在，我们要正式进入核心的业务层。

二、 第二阶段详细任务拆解 (限时 4-5 天)
👨‍💻 组员 3：后端业务写入（余雨航）
本阶段你是后端的主力军，负责整个项目最核心的积分流转机制。
【任务 1】完善与测试获取学生列表 API
• 负责文件: `professor_api.py`
• 具体事务: 确保 GET /api/students 接口能正确返回所有角色为学生（role=0）的用户列表。此接口需要教授鉴权 (@role_required(1))。

【任务 2】完善与测试积分提交与日志 API
• 负责文件: `professor_api.py`
• 具体事务: 
  1. 完善 POST /api/points 接口，接收前端的 student_id、score_change、reason。将数据写入 point_log，并确保此时数据库中的 trg_after_point_insert 触发器能成功更新 house 表的积分。
  2. 完善 GET /api/professor/logs 接口，通过联合查询返回教授的历史操作日志。

👨‍💻 组员 4：后端业务读取（费翔鸿）
本阶段你需要完成学生端的基础数据读取接口，为前端的展示提供数据源。
【任务 1】完善学生基础信息与日志读取 API
• 负责文件: `student_api.py`
• 具体事务: 
  1. 完善 GET /api/student/info 接口，联查 sys_user 与 house 表，返回学生的姓名和学院信息。需要学生鉴权 (@role_required(0))。
  2. 完善 GET /api/student/logs 接口，查询当前学生在 point_log 中的加扣分明细。

👩‍💻 组员 1：前端开发（甄珍）
你的任务是将余雨航和费翔鸿提供的 API 与界面绑定。
【任务 1】教授端工作台联调
• 负责文件: 新建 `professor.html` (或相应组件) 及配套 js
• 具体事务: 
  1. 页面加载时调用 GET /api/students，将返回的学生数据填入下拉框。
  2. 提交表单时调用 POST /api/points 提交分数变动。
  3. 调用 GET /api/professor/logs 获取历史记录并以表格展示。
【任务 2】学生端个人中心联调
• 负责文件: 新建 `student.html` (或相应组件) 及配套 js
• 具体事务: 
  1. 调用 GET /api/student/info 展示个人信息及学院。
  2. 调用 GET /api/student/logs 渲染积分通知列表，根据分数正负使用红/绿色区分。

👨‍💻 组长兼技术统筹（石雯珏 / Noa）
本阶段你主要负责整体架构的代码合并、冲突处理与集成测试把关。
【任务 1】代码 Review 与业务流集成测试
• 具体事务: 
  1. 负责在 GitHub 审核并合并余雨航和费翔鸿的代码分支，确保代码没有冲突、排版整洁、注释紧凑。
  2. 在本地主分支运行完整闭环测试：注册一个测试教授账号和一个测试学生账号。使用教授账号给学生加分，验证数据库中的 point_log 是否产生记录，以及对应 house 的 total_points 是否通过触发器正确累加。
